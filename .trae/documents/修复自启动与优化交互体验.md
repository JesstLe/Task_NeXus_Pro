- 自启动：前端勾选后会先写配置 `launchOnStartup`，再调用 `set_admin_autostart` 创建任务计划；若任务计划创建失败，配置不会回滚，导致“看起来开了但实际没生效”。入口见 [App.tsx:L202-L224](file:///e:/Documents/WorkSpace/TN/src/App.tsx#L202-L224)，实现见 [main.rs:L67-L127](file:///e:/Documents/WorkSpace/TN/src-tauri/src/main.rs#L67-L127)。
- 网络优化：`optimize_network(true)` 会改 `*InterruptModeration=0` 等高风险项，且回滚不完整（省电 WMI 关闭不回滚，FlowControl/Jumbo 不回滚，NetworkThrottlingIndex 回写固定值）。见 [optimizer.rs:L324-L343](file:///e:/Documents/WorkSpace/TN/src-tauri/src/optimizer.rs#L324-L343)。
- 配置应用/状态：profiles 保存不等于已应用；是否生效依赖后端监控 tick 自动 enforce，且 UI 没有清晰“当前正在应用哪些规则/上次应用结果”。链路见 [watchdog.rs:enforce_profiles](file:///e:/Documents/WorkSpace/TN/src-tauri/src/watchdog.rs) 与 `process-update` 事件 [monitor.rs](file:///e:/Documents/WorkSpace/TN/src-tauri/src/monitor.rs)。

## 目标（对应用户反馈）
1. 自启动：让用户能看到“系统层是否真的启用”，并减少“勾选无效/状态不一致”。
2. 网络优化：降低触发 DPC 飙升的概率；并提供“可逆/可恢复到变更前”的恢复路径与提示。
3. 交互：保存的配置要有明确的“应用/正在应用/已生效”状态，不再靠猜。
4. 核心序列测试：提供“一键按序绑定不同核心并显示当前步骤/状态”的工具，并可导出/导入后点应用生效。

## 改动方案（后端）
### A. 自启动可靠性
- 新增 Tauri 命令 `get_autostart_status()`：查询任务计划 `TaskNexusAutoStart` 是否存在、触发器/RunLevel/Action 路径是否匹配当前 exe，并返回结构化状态（enabled/exists/mismatch/error）。
- 调整 `set_admin_autostart(enable)`：
  - enable=true 成功后再写入配置；失败则不写入（或回滚）避免“配置开了但系统没开”。
  - 对常见失败原因做更明确错误信息（无权限/PowerShell 不可用/任务计划服务异常）。
- 增加“非管理员 fallback”（可选）：当无法创建最高权限任务计划时，提示用户并提供普通 Run 键方式（HKCU Run）作为备选（不需要管理员但权限较低）。

### B. 网络优化降低风险 + 完整回滚
- 拆分为“安全模式/激进模式”两档：
  - 安全模式默认不动 `*InterruptModeration`（避免 DPC 风险），只做较低风险项。
  - 激进模式保留现有行为，但 UI 必须提示“可能导致 DPC 飙升/需重启”。
- 引入“变更前快照”机制：启用前把所有将要修改的注册表值原值保存到应用配置/单独备份区；恢复时按快照精确还原（不存在则删除）。
- 补齐回滚缺口：
  - `*FlowControl/*JumboPacket` 恢复原值。
  - WMI 省电开关的变更记录与回滚（或至少改为仅针对网卡设备，不要全量 MSPower_DeviceEnable）。
  - `NetworkThrottlingIndex` 恢复为“原值/未设置”而不是写死 10。

### C. 配置应用/状态可视化
- 新增“应用动作回执事件”：对手动应用/批量应用/自动 enforce，后端 emit `apply-status`（包含 pid、操作类型、目标 mask、成功/失败、原因）。
- 为 profiles 增加显式“立即应用”命令：`apply_profile_to_running_processes(profileName)`（只对当前运行的匹配进程执行一次），用于用户保存后立刻点“应用”。
- 自动应用开关持久化：将 `AUTO_ENFORCE_ENABLED` 写入配置（例如 `autoEnforceEnabled`），重启后保持用户选择。

### D. 核心序列测试（按序绑定）
- 新增后端命令 `run_affinity_sequence(pid, steps, intervalMs, mode)`：按步骤依次设置亲和性/CPU sets，每步 emit 当前进度与结果（可中止）。
- steps 支持：单核序列、按 group(CCD) 序列、用户自定义 mask 列表。
