## 可行性结论
- 严格意义上的“把某个逻辑核心限制为最多 X% 被占用”在 Windows 上**没有直接、稳定的系统级 API**（按“核心”做百分比上限）。
- 但可以实现你真正想要的效果：**让某些进程/后台任务最多用掉 X% CPU，从而不给目标核心/前台任务造成抢占**。
- 现有代码已经具备两种可用的基础能力：
  - **硬/软绑核**：进程亲和性 mask（硬），CPU Sets（软）
  - **优先级调度**：进程优先级（含 ProBalance 自动降优先级）

## 推荐方案（最接近“最大占用多少”）
- 新增“CPU 限速/占用上限（百分比）”能力：用 Windows **Job Object CPU Rate Control** 给指定 PID 设置 CPU 上限（例如 20%/50%）。
- 同时允许用户指定“核心集合”（亲和性/CPU Sets），把该进程限定在某些核心上运行；这样“上限 + 核心集合”组合后，实际效果就非常接近“某个核心最多占用多少”。

## 兼容与回退策略（必须做）
- 某些进程可能已经在别的 Job 内，`AssignProcessToJobObject` 可能失败（常见错误 `ACCESS_DENIED`）。
- 失败时提供两级回退：
  - 回退 1：只应用 CPU Sets/亲和性（把后台进程挪到 E 核/非关键核心）
  - 回退 2：只降优先级（已有能力，且 ProBalance 已在用）
